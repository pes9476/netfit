# 2026-09-14 · 웹 우선 / 카카오 로그인 / 닉네임 표시

## 현재 단계와 팀 결정

현재는 Django 화면·인증·운동 기록을 연결한 프로토타입이다. 넷핏 핵심 흐름 전체가 완성된 상태는 아니다.

- 사용자 로그인은 카카오로 진행한다.
- 닉네임은 사용자가 설정한 경우 표시한다.
- 웹 기능을 우선 완성하고, 모바일 앱은 필요할 때 검토한다.
- 보상은 경험치와 레벨업을 기본으로 한다. 추가 보상과 그룹 경쟁 규칙은 추후 논의한다.
- 9월 25일 기능 완성, 9월 30일 전 버그 수정 후 제출을 목표로 한다.

## 왜 바꿨나 / 문제

일반 로그인과 카카오 로그인이 함께 보여 사용 경로가 나뉘었다. 카카오 최초 회원은 긴 임시 ID 또는 '운동친구'라는 대체 이름이 표시됐다.

## 어떻게 해결했나

1. `/login/`에서 카카오 인증 시작 링크만 제공한다. 기존 비밀번호 POST로 세션을 생성하지 않는다.
2. `/register/`는 카카오 로그인 안내로 이동한다. 기존 회원을 삭제하지 않는다.
3. `Profile.display_name`은 카카오 임시 ID라면 빈 문자열을 반환한다.
4. 헤더는 이름이 없으면 '닉네임 설정' 링크를 보여준다. 카드·친구 화면도 빈 이름을 자연스럽게 처리한다.
5. 프로필에서 별명을 저장하고 다시 로그인하면 기존 카카오 고유 ID로 같은 사용자를 찾는다.
6. 경험치 계산은 변경하지 않고 기존 지급·레벨업 동작을 테스트했다.

## 변경 파일

- `fitness/views.py`: 사용자 로그인·회원가입 진입 경로 정리
- `fitness/models.py`: 임시 이름을 공개 이름으로 반환하지 않도록 수정 (필드 변경 없음)
- `fitness/templates/fitness/login.html`, `home.html`: 카카오 로그인 안내
- `fitness/templates/fitness/base.html`: 닉네임 또는 설정 링크 표시
- `fitness/templates/fitness/battle.html`, `battle_arena.html`, `friends.html`: 빈 이름 처리
- `fitness/test_kakao.py`: 기존 계정 보존, 카카오 전용 진입, 닉네임 표시 검증
- `fitness/tests_selenium.py`: 비밀번호 폼 대신 카카오 링크를 검증
- `fitness/test_web_flow.py`: 비로그인 보호 경로와 경험치·레벨업·세션 검증
- `KAKAO_LOGIN.md`: 현재 로그인 안내 갱신

## 변경하지 않은 부분과 이유

카카오 OAuth, DB 필드, migration, 환경변수, secret, 배포 설정은 변경하지 않았다. 기존 경험치 계산과 로그아웃 후 홈 이동도 유지했다.
일반 계정 및 관리자 로그인은 삭제하지 않았다. 카카오와 일반 계정의 자동 병합도 하지 않았다.
사진 업로드·승인, 건강앱 자동 수집, 그룹 경쟁 규칙은 이번 범위가 아니다.

```powershell

```

- Django check: 문제 없음
- 자동 테스트: 12개 통과
- headless Chrome: 실제 로그인 페이지의 카카오 링크 확인
- 카카오 API 응답은 모의 처리: 신규 생성, 재로그인, 비활성 계정, 취소, 상태 만료, 통신 실패 검증
- 실제 카카오 외부 동의 화면은 이번 작업에서 재검증하지 않음
- 브라우저 테스트 종료 중 Broken pipe 로그가 있었지만 테스트는 통과함
- 기존 로컬 사용자 DB를 테스트용으로 사용하지 않음

## 화면·동작을 공부할 때

| 사용자 행동 | 연결 지점 | 서버 처리 / 결과 |
|---|---|---|
| 로그인 버튼 클릭 | login.html의 kakao_login URL 이름 | kakao.py가 인증 상태를 세션에 저장하고 카카오로 이동 |
| 카카오 인증 완료 | /login/kakao/callback/ | 고유 ID로 회원 조회·생성 후 Django 세션 로그인 |
| 닉네임 저장 | profile.html → ProfileForm | 기존 username 필드에 저장, display_name으로 표시 |
| 운동 기록 저장 | activity.html → record_workout | WorkoutRecord 저장 → 경험치 지급 → 레벨 계산 |
| 로그아웃 버튼 | base.html의 POST form + CSRF | LogoutView가 세션 종료 → / 공개 홈 |

디자인 수정 시 URL 이름, form의 method/action, CSRF 토큰, JavaScript가 참조하는 id/name을 임의로 바꾸지 않는다. 스타일은 바꿀 수 있지만 연결 지점은 테스트와 함께 확인한다.

## 위험과 남은 문제

- 기존 일반 계정은 사용자 로그인 화면에서 비밀번호로 로그인할 수 없다. 기존 기록 이전 정책은 별도 결정이 필요하다.
- 닉네임은 아직 username을 사용한다. DB 분리나 기존 계정 마이그레이션을 수행하지 않았다.
- 사진 인증·중복 보상 방지가 없으므로 현재 경험치는 검증된 운동 증거가 아닌 수동 기록 기준이다.
- 기존 운동 입력 검증, 프로필 저장 시 측정 기록 중복, 테스트 레벨 변경 경로, 공개 배포 설정은 후속 점검 대상이다.
- 기존 avatar_preference 모델 선택지와 migration 불일치는 남아 있다. 기존 migration은 수정·삭제하지 않았다.
- 실시간 카카오 인증 및 모바일 브라우저 뒤로가기 검증이 필요하다.
